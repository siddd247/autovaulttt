Six Pillars of AutoVault Security Architecture

Each defense mechanism is implemented directly in the core codebase and verifiable via automated unit tests.

A. Cryptographic Hashing

CREDENTIAL INTEGRITY

Plaintext passwords are never committed to storage. Passwords are automatically salted and processed using Werkzeug's PBKDF2/scrypt password hashing functionality before database persistence.

// app/models/user.py
def set_password(self, password):
self.password_hash = generate_password_hash(password)

B. IDOR Access Controls

OBJECT TENANCY ENFORCEMENT

Database lookups strictly enforce user ownership. Attempts to access another user's protected objects (vehicles, fuel logs, service records, reminders, documents) through manipulated identifiers return HTTP 403 Forbidden responses.

// IDOR Tenancy Verification Check
if object.vehicle.user_id != session['user_id']:
abort(403) # HTTP 403 Forbidden

C. SQLi Protection via ORM

PARAMETERIZED QUERY CONSTRUCTION

Database operations use SQLAlchemy ORM and parameterized queries to reduce SQL injection vulnerabilities. Inputs are treated as pure data literals and never concatenated directly into raw SQL string expressions.

// Parameterized ORM Invocation
Vehicle.query.filter_by(
id=vehicle_id, user_id=current_user.id
).first_or_404()

D. Anti-Enumeration Logic

UNIFORM FAILURE HANDLER

Authentication failure handlers return uniform responses, making it substantially more difficult to discover registered usernames or email addresses through error-message differences or timing discrepancies.

// Uniform Status Response
if not user or not user.check_password(password):
flash('Invalid username/email or password.', 'danger')

E. Isolated Quarantining

SECURE GATEWAY SERVING

Uploaded documents are stored outside the public web root (in instance/uploads/documents/), with strict extension whitelisting (.pdf, .png, .jpg, .webp), cryptographic UUID renaming, and authenticated gateway serving.

// Quarantine Renaming & Delivery
safe_name = f"{uuid.uuid4().hex}.{ext}"
send_from_directory(upload_dir, doc.stored_filename)

F. XSS Output Sanitization

CONTEXTUAL HTML ESCAPING

User-supplied information displayed in the interface is HTML-escaped through Jinja2 contextual escaping to help prevent stored and reflected Cross-Site Scripting (XSS) attacks across vehicle notes, filenames, and workshop descriptions.

// Jinja2 Contextual Auto-Escaping
<td>{{ record.description }}</td>
